## ファイル

## 構成と編集方針

1. 強みの概要：つくる・運用する・共有する。
2. yt-factory：YouTubeとブログを同時に運営し、週1回、動画・記事を公開。
3. 設計上の工夫：工程分担、再実行、自動検品と人による確認。
4. Qiita・note：記事への反響と、Qiitaをベースにした業務内の知見共有。
5. お客様の業務への応用案：資料作成、コンテンツ展開、チーム内共有。

既存の公開サイトは変更していません。自然言語AIモデル開発の案件は含めていません。
屋号、代表、開業、収益化、個人の受託窓口は掲載していません。
個人での構築・運用と、業務内の知見共有は区別しています。
所属・実名は未提供のため、既存プロフィールの「SHOU / ITエンジニア」を使用しました。

構成はbrainstormingスキルの観点で整理し、初版を見て改善したいという依頼に沿って作成しました。
frontend-designスキルを用い、16:9・白地と濃紺・図解と大きめの日本語文字で、商談時に説明しやすい体裁にしています。

## 根拠と数値の扱い

- 週1回の動画・記事公開、Qiitaの27いいね、noteの32スキ、業務内でのQiitaベースの知見共有は、2026-09-08の本人申告を使用しています。外部サイトで再集計はしていません。
- 数値がAI記事のみの合計かアカウント全体かは未確認のため、スライドでは「AI記事のみの累計」と断定していません。次版で集計対象を明確にすると、より説明しやすくなります。
- yt-factoryの設計説明は、`../../_contents/projects/yt-factory.md`を参照しています。
- 運用頻度は本人の今回の説明を優先し、既存サイトにある動画50本超などの過去の数値は採用していません。
- チームのスキル向上率、削減時間、コスト削減、企業への導入実績は追加していません。
- 最終ページは既存の経験から考えられる応用案です。実施済みの顧客案件とは区別しています。

## 次版で具体化するとよい点

- 提示時の氏名・所属表記。
- 代表的なAI記事のタイトル・URL（Qiita、note各1〜2本）。
- 業務内で共有した具体的なテーマと、メンバーの反応・活用例。
- 週次運用を継続している期間と、紹介可能な動画・ブログ記事の組み合わせ。
- 測定できる場合は、作業時間・修正量・工程の再実行頻度など。

外部プロフィールには個人事業の説明が含まれる可能性があるため、初版のスライドには未確認のプロフィールリンクを掲載していません。紹介記事が決まったら、該当する記事単位で参照を追加できます。

## PDFの再出力

HTMLをChrome / Chromiumで開き、「印刷 / PDFに保存」を押します。
用紙サイズはCSSで16:9に指定しています。余白なし、背景グラフィック有効、ヘッダー・フッター無効で保存してください。

コマンドでの生成例（リポジトリのルートから実行）：

```bash
chromium --headless --no-sandbox --disable-gpu --no-pdf-header-footer --print-to-pdf=docs/client-ai-portfolio/ai-portfolio-v1.pdf --timeout=10000 file:///workspaces/shou-portfolio/docs/client-ai-portfolio/ai-portfolio-v1.html
```

この環境ではNoto Sans JPフォントを使用しました。他の環境では同フォントをインストールすると配置を揃えやすくなります。
