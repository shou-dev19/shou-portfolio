# yt-factory — AI駆動 YouTube動画制作 自動化パイプライン

個人運営の格安SIM（MVNO）比較YouTubeチャンネルを支える、**企画立案から動画公開・ブログ展開までをほぼ全自動化した動画制作基盤**。生成AIエージェントと従来型のWeb技術を組み合わせ、通常はチーム体制が必要な「リサーチ → 台本 → スライド → 音声 → 動画 → サムネイル → 公開 → 記事化」の一連の工程を一人で回せる仕組みとして構築した。

## アピールポイント

### 1. 企画から公開までのフルパイプライン自動化

テーマを1つ入力するだけで、以下が一気通貫で動く設計。

```
台本生成（AIエージェント）
  → スライド画像生成（Vite + React + Puppeteer）
  → 音声合成（VOICEVOX）＋ 動画レンダリング（Remotion）
  → サムネイル生成
  → YouTube Data API（OAuth 2.0）で限定公開アップロード
```

各工程は独立した submodule として疎結合に保ち、`bridge.sh` による成果物の受け渡しでパイプライン化。工程単位での再実行・差し替えが容易な構成にしている。

### 2. マルチエージェント体制のハーネス設計・運用（Claude Code × Antigravity CLI × Codex）

複数の AI エージェント基盤を組み合わせ、**それぞれの強みに応じてタスクを振り分けるオーケストレーター／サブエージェント体制**を設計・運用している点が特徴。

- **役割分担の設計**: Claude Code をオーケストレーターとし、Google 検索を要するリサーチ工程は Antigravity CLI（Gemini）へ、実装のセカンドオピニオンや原因調査は Codex へ委譲。各エージェントの得意領域（検索・調査・生成・レビュー）に基づくタスク譲渡を skills として定義
- **委譲の信頼性設計**: 委譲プロンプトのテンプレート化（テンプレートを唯一の正とし毎回の組み立てを排除）、CLI 呼び出しのラッパースクリプト化による permission allowlist の決定論化、stdin ハンドリングやバックグラウンド実行の制御など、エージェント間連携で実際に起きた障害を一つずつ潰し込んだ運用ノウハウを蓄積
- **フォールバック設計**: 委譲先エージェントが利用不可・失敗上限に達した場合はオーケストレーター自身が代替手段（WebSearch 等）で同一フォーマットの成果物を出す、実行環境（ローカル／クラウド）に応じた分岐など、無人運転でも止まらない冗長構成

### 3. ループエンジニアリング — 無人で回り続ける日次自動化

エージェントを単発で使うのではなく、**スケジュール起動で毎日自律的に完遂するループとして設計・運用**している。

- **日次自動企画ループ**: クラウドのスケジュール実行（Routine）で毎朝7時に新規セッションとして起動。業界ニュース収集（公式サイト10社の巡回＋差分検知）→ 自チャンネルの傾向分析 → 競合チャンネル分析 → 企画案の生成・スコアリング・自動採用 → 台本ドラフト作成までを無人で完遂し、結果をプッシュ通知
- **オーケストレーター型スキル設計の4原則**: パイプライン状態のファイル永続化（中断・再開可能）、プロンプトのテンプレート化、lint による成果物検証、リトライ上限の設定 — AIの不確実性を前提とした耐障害設計
- **運用からの継続改善**: 実運用で発生した失敗（ハング・分類器拒否・空応答）を原因調査 → スキル定義への恒久対策の反映というサイクルで改善し、無人成功率を向上
- **品質担保の3層構造**: 生成ルールの薄型化＋参照台本による few-shot＋自動検品スキル。さらに「おすすめ判断が運営者の決定木と矛盾していないか」を検査するロジック検品も別スキルとして実装

### 4. React × Remotion によるプログラマブルな動画生成

- 動画を React コンポーネント（TypeScript / Tailwind CSS 4 / Zod スキーマ検証）として実装し、コードで完全制御
- 台本の話者・感情データに連動するキャラクターアニメーション、図鑑風見開きスライド＋カメラ演出などのリッチ表現
- Google Veo による生成AI動画クリップの挿入にも対応

### 5. GitHub Actions を使ったクラウドレンダリング基盤

- ローカルマシンに負荷をかけず、`workflow_dispatch` でリモートの動画レンダリングを実行（依存キャッシュ・CJKフォント・ffmpeg 環境を整備）
- 通信速度データの週次自動取得など、データ更新系のワークフローも自動化
- 共有アセットは `shared/` に一元管理し、rsync による配布スクリプトで CI・ローカルの整合性を担保

### 6. データドリブンなチャンネル運営

- 料金プランデータは Python で CSV → JSON → HTML に変換するデータ管理基盤を整備し、台本・スライド・記事すべてが同一データを参照
- YouTube Analytics の分析から「クリック率ではなく登録転換率がボトルネック」と特定し、速報シリーズ化・中盤CTA・Shorts送客などの改善策を実装
- UTMパラメータの命名規約を定め、動画→ブログの流入計測を既存動画50本に一括適用（API経由の一括更新スクリプトを自作）

### 7. マルチチャネル展開の自動化

動画だけでなく、同じ台本データから **WordPressブログ記事・note記事への横展開**も自動化。

- Markdown → WordPress（Cocoon テーマ）用 HTML 変換＋アイキャッチ画像生成＋REST API での下書き投稿までワンコマンド
- CTAブロックやアフィリエイトリンクはマスターデータ（JSON/CSV）で一元管理し、検品スクリプトで整合性チェック

## このプロジェクトで示せるスキル

- **AIエージェント設計**: マルチエージェント体制の構築（Claude Code・Antigravity CLI・Codex）、skills ハーネスによるオーケストレーター／サブエージェントの役割分担設計、ループエンジニアリング（スケジュール起動の無人ループ設計・運用）
- **生成AI活用**: LLMエージェントのプロンプト設計、AI成果物の自動検品・品質管理、フォールバック／リトライを含む耐障害設計
- **フロントエンド**: React 19 / TypeScript / Tailwind CSS / Vite / Remotion による動画・画像のプログラマブル生成
- **自動化・CI/CD**: GitHub Actions（クラウドレンダリング、定期データ取得）、シェルスクリプトによるパイプライン構築
- **API連携**: YouTube Data API（OAuth 2.0）、WordPress REST API、Google Veo
- **データエンジニアリング**: Python によるデータ変換基盤、スクレイピング＋差分検知
- **プロダクト運営**: 分析に基づく改善サイクル、計測設計（UTM）、コンテンツSEO
